# Implementation status

Snapshot: 2026-11-26, current working tree, including uncommitted changes. This
is not a release or deployment approval. See [test status](TEST_STATUS.md) for
the scope and date of the latest runs.

Statuses: **NOT STARTED**, **IN PROGRESS**, **IMPLEMENTED**, **TESTED**, and
**BLOCKED**. An IN PROGRESS item may have passing tests for a subset of its
behavior; that does not make the entire requirement TESTED.

| Requirement | Status | Evidence and limitations | Remaining work / dependencies |
| --- | --- | --- | --- |
| Live Flattrade and trading gate | IN PROGRESS | [Flattrade routes](../steadfast-api/routes/flattrade.js) enforce a trading gate, session and 1–10 whole lots per server-managed order; API tests pass. The checked-in production unit explicitly enables trading. A successful response is not a confirmed fill. | Keep the agreed configuration unchanged unless explicitly authorized; add broker readiness and reconciliation before new trades. Verify the unit's live-enabled default against the agreed startup safeguard. |
| No simulated production orders | IN PROGRESS | [/virtual](../steadfast-api/routes/virtual.js) returns 403 in every profile and has a gate test. Production blocks Shoonya; legacy development still supports it. | Explicit PAPER/SIMULATION mode rejection and complete runtime enforcement are not verified. |
| Central broker reconciliation | IN PROGRESS | [Reconciliation service](../steadfast-api/reconciliationService.js) starts with the API, runs an initial cycle and schedules three-second bulk reads of positions, M/I orders and trades. It is single-flight, uses a SQLite lease for processes sharing one database, retries with bounded backoff and exposes health/status. Order, cancel, session, uncertain-exit and authenticated WebSocket reconnect events request immediate cycles. | Broker rate limits and long-term history completeness are unverified. Separate hosts with independent SQLite files are not coordinated; only one API service is deployed. No modification-order route exists. |
| First-fill manual and default protection | IN PROGRESS | [Lifecycle reconstruction](../steadfast-api/positionLifecycle.js) and [risk routes](../steadfast-api/routes/risk.js) reconcile same-day position and trade books for manual/default creation and before automated exit. Startup/session expiry suspend rules; the scheduler restores a suspended rule only when broker evidence matches its saved lifecycle and any exit order is resolved. | Unverifiable carry-forward or ambiguous lifecycles remain `ACTION REQUIRED`; historical continuity and evidence intake/resolution are not implemented. Rule storage remains symbol-keyed; external trading after the snapshot can invalidate it. |
| Virtual fixed SL and target | IN PROGRESS | [WebSocket monitor](../steadfast-websocket/risk_monitor.py) evaluates server-selected rules; optional UI monitoring checks fresh per-position quotes and sends trigger signals to the API. The API validates monitor, trigger price, reason, revision and opening fill before placing exits. The reconciler independently checks resulting broker state. | API-side quote age is not checked. Reconciliation does not submit an exit based on stale prices if real-time monitoring misses a trigger. |
| Trailing SL and target trailing | IN PROGRESS | Default entry settings now pass selected trailing-stop or target-trailing mode and points to the API; both monitor paths preserve directional arithmetic and avoid non-advancing target-trail increments. | Tick-size validation, quote ordering/freshness, durable error reporting and reliable progress recovery remain incomplete. |
| Centralized exit service | IN PROGRESS | Both server and UI monitors submit trigger signals to the API; neither browser monitor places broker orders directly. Flattrade PlaceOrder acknowledgement persists `exit_pending` and the broker order ID. The reconciler adopts a matching active exit and reconciles terminal/partial order state. | Manual exits still use a separate browser order path; uncertain or unmatched exits remain `ACTION REQUIRED` and are never blindly retried. No shared manual/automatic exit service or bounded cancel/replace policy exists. |
| Percentage partial exits | NOT STARTED | No 25/50/75/100% workflow or confirmed remaining-quantity tracking. | Requires centralized exits, lot rounding/validation, and broker reconciliation. |
| Broker order and fill reconciliation | IN PROGRESS | Three-second cycles compare bulk PositionBook, OrderBook M/I and TradeBook data; order fill summaries, remaining quantity and weighted average fill prices are persisted when changed. Pending exits, active orders and flat positions are reconciled against broker evidence. | Broker history retention/completeness and read-endpoint rate limits are unverified. Cross-day lifecycle recovery, all product types, independent-host locking and complete execution/cancellation resolution remain incomplete. |
| Marketable-LMT exit repricing | NOT STARTED | Existing exit paths use a 2% LTP buffer and a fixed 0.05 tick; no bounded cancellation/replacement lifecycle. | Obtain fresh depth, instrument tick size and price bands; implement the agreed three-attempt policy and confirm cancellation and remaining quantity before replacement. |
| Per-position state and audit history | IN PROGRESS | SQLite persists symbol-keyed rules and opening-fill identity; rule revisions guard trailing progress. | Stable account/exchange/product/lifecycle identity, execution and edit history, timestamp ordering, and safe concurrent updates remain incomplete. |
| Lot-level expandable positions | IN PROGRESS | [Positions table](../steadfast-app/src/components/PositionsTableComponent.vue) expands broker-aggregated positions into derived lot rows; expansion state persists locally and lot rows show entry, exit, realized and unrealized values. [Lot ledger](../steadfast-api/lotLedger.js) persists independently keyed lot allocations in SQLite and is exposed by `/flattrade/lots`. | Broker lot identity is not guaranteed: rows are allocated from available entry fills and explicit legacy allocations are used when history is unavailable. Independent lot protection/exit execution, exact FIFO fill allocation, WebSocket lot events and restart restoration are not yet complete. |
| UI controls and status | IN PROGRESS | Entry screen exposes fixed SL/target, trailing SL, target trailing, and a server/UI monitor toggle. Position rows omit warning details; concise statuses are shown in the global notification panel. Account data refreshes every three seconds without a page reload. Buy Both/Sell Both submit CE then PE; LMT legs use sequential price dialogs. P&L summary separates gross, estimated tax, other fees, brokerage, total charges and net. UI monitoring requires this tab and fresh quotes. | Charges use broker pricing estimates, not contract-note values. Actual exit fills and realized P&L are not yet displayed. No trusted evidence intake/resolution exists for states the broker history cannot verify. |

Virtual rules are not exchange-side protection. Feed, backend, network or broker
failure, or an unfilled order, can leave a position open. Do not treat this
snapshot as evidence that live exits or recovery are safe.
